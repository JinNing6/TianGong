## 🚀 起火入道 (Quick Start)

### 凝练实体 (Install)

```bash
pip install tiangong-mcp
```

或将源码搬入洞府：

```bash
git clone https://github.com/JinNing6/TianGong.git
cd TianGong
pip install -e .
```

### 接入神识 (Run MCP Server)

配置你的大模型客户端（如 Claude Desktop、Cursor）：

```json
{
  "mcpServers": {
    "tiangong": {
      "command": "tiangong-mcp",
      "env": {
        "GITHUB_USERNAME": "your_username"
      }
    }
  }
}
```

恭喜，你已踏入修真。

### 第一条 MCP 命令

MCP Server 接入后，在你的客户端里运行：

```text
start_cultivation(username="your_github_username")
```

它会返回 MCP 配置、第一条 `forge_agent` 命令、`activation_funnel()` 复查、`growth_flywheel()` 复查、`public_launch_preflight()` 复查、GitHub Growth Issue 回流 URL，以及可复制首会话入门战书；不会伪造灵力或注册成功。

## ✅ 开发质量门

任何新的任务、境界规则或公开增长入口准备推广前，先安装完整本地质量门，并运行与 CI 一致的检查：

```bash
python -m pip install -e ".[dev]"
python -m ruff check .
python -m pytest -q
tiangong-mcp public-launch-assets
python -m build
python -m twine check dist/*
tiangong-mcp public-proof-pack --target-contributors 10
tiangong-mcp public-release-boundary
```

`.github/workflows/quality-gates.yml` 会在 push 和 pull request 中安装同一个 dev extra，并用只读仓库权限执行 lint、测试、构建和包元数据检查。

`.github/workflows/publish-pypi.yml` 会在 GitHub Release 发布时向 PyPI 发版；如果当前无法创建 Release，也支持对一个已存在的 `v*` tag 使用受保护的手动 `workflow_dispatch` 兜底。workflow 会检出该 tag，校验 tag commit 已经能从 `origin/main` 追溯，校验 `pyproject.toml` 版本与 tag 一致，重新执行 lint、测试、本地 launch asset audit、构建、`twine check` 和 public release-boundary check，然后通过 `pypa/gh-action-pypi-publish@release/v1` 使用 PyPI Trusted Publishing 和 job 级 `id-token: write` 发布，因此发版路径不需要保存 `PYPI_TOKEN`。

`tiangong-mcp public-launch-assets` 还会输出完整公开增长 release handoff：创建 `v0.1.0` GitHub Release 之前需要 staging 的文档、包元数据、Issue Forms、workflows、公开增长模块、用户可见增长表面和测试。

## 🎮 修炼指南 — 完整七步

> *安装完成，你已踏入修行之路。以下是完整的修炼指南。*

<br/>

### 🧑 第一步：凡人入门 — 开炉炼器

你的第一件法宝（Agent）就是你的入门仪式。

```
forge_agent(name="my-first-agent", description="A helpful coding assistant", creator="your_github_username")
```

- ✅ 创建成功后，你就从**凡人**晋升为**炼气期**修仙者
- ✅ 你的 Agent 会被注册到全平台 registry，所有人都能搜到它
- ✅ 你获得 +100 灵力值（Spirit Power）
- ✅ 境界晋升受真实档案门槛约束：首次 +100 灵力开炉只进入**炼气期**，不会在法宝数量不足时跳到结丹期
- ✅ 欢迎仪式会生成可复制分享文案，并引导你继续 `publish_agent`、`infuse_spirit`、`quest(action="browse")`
- ✅ 每次炼器成功都会生成法宝出世分享文案，并直接引导 `refine_agent`、`publish_agent`、`treasure_pavilion`、`my_realm`、冲击法宝天榜

<br/>

### 🔥 第二步：千锤百炼 — 淬炼法宝

法宝不是一蹴而就的。每次改进你的 Agent，都要记录淬炼：

```
refine_agent(agent_id="your-agent-id", changes="Added error handling and retry logic")
```

- ✅ 每次淬炼 +30 灵力值
- ✅ 淬炼次数越多，法宝在天榜的排名越高
- ✅ 淬炼成功会生成可复制分享文案，并引导你继续 `publish_agent`、`infuse_spirit`、查看 `my_realm()`、冲击法宝天榜

<br/>

### ✨ 第三步：发布出世 — 法宝入阁

当你的法宝准备好了，将它发布到寻宝阁供天下修仙者使用：

```
publish_agent(artifact_name="my-first-agent")
```

- ✅ 法宝进入社区寻宝阁，所有人都能搜索和拉取
- ✅ 其他修仙者可以对你的法宝进行六维鉴定（评价）
- ✅ 发布成功会生成可复制分享文案，并引导你邀请道友 `infuse_spirit`、查看 `treasure_pavilion`、争夺法宝天榜
- ✅ 发布失败会披露真实本地/配置失败快照，不伪造寻宝阁条目，并返回开炉、洞府、悬赏、搜索、冲榜恢复命令
- ✅ 寻宝阁搜索结果会为每件法宝直接生成召唤、鉴定、传承、冲榜和分享动作
- ✅ 寻宝阁无结果时会披露真实 0 结果快照，并把空缺变成可复制寻宝令，直接引导 `quest(action="post")` 和 `forge_agent`
- ✅ 寻宝阁 action 错误会披露支持的公开动作，不静默伪造成搜索结果，并返回可复制纠错命令
- ✅ 请宝下凡成功会生成可复制分享文案，并引导你继续 `infuse_spirit`、查看 `my_vault()`、追溯传承、冲击法宝天榜
- ✅ 请宝失败会披露真实寻宝阁/藏宝阁失败快照，不伪造本地安装，并返回搜索、悬赏、开炉、洞府、冲榜恢复命令
- ✅ 追溯传承会返回 GitHub Issue 真实谱系快照、传承灵力加成、来源 Issue 证据和可复制道统分享文案

<br/>

### 🔮 第四步：以评证道 — 鉴定他人法宝

修仙不是闭门造车。评价他人的法宝，既能积累灵力，又能提升自身境界：

```
infuse_spirit(artifact_name="some-agent", inscription=8, formation=7, technique=9, lineage_score=6, resilience=8, enlightenment=7, comment="Great design!")
```

六维评价体系：
| 维度 | 含义 | 对标 |
|------|------|------|
| 📝 铭文 | 描述是否清晰 | README 质量 |
| 🏗️ 阵法 | 架构是否优雅 | 代码架构 |
| ⚙️ 法诀 | 工程是否扎实 | 代码质量 |
| 📖 道统 | 文档是否传承 | 文档完整度 |
| 🛡️ 护体 | 是否稳定可靠 | 鲁棒性 |
| ✨ 悟道 | 是否有创新 | 创新性 |

> 💡 你的境界越高，评价权重越大 — **一位大天尊的 5 分评价，灵力价值远超炼气期修仙者的满分。**

- ✅ 鉴定成功会生成可复制分享文案，并引导你继续 `infuse_spirit`、查看 `my_realm()`、冲击 `leaderboard(type="season")`
- ✅ 鉴定评分错误会披露公开 1-10 评分规则，不伪造鉴定结果或灵力奖励，并返回可复制恢复命令
- ✅ 鉴定资格失败会披露真实修仙者档案/上限快照，不伪造鉴定或灵力奖励，并返回开炉、发布、搜索、悬赏、名片、赛季天榜恢复命令

<br/>

### ⛰️ 第五步：拜入宗门 — 群体修炼

当你的境界达到**结丹期**（level 3）时，你可以创建自己的宗门；也可以随时加入已有的宗门：

```
sect(action="create", sect_name="天剑宗", motto="以剑入道，万法归一")     # 开宗立派
sect(action="join", sect_name="天剑宗")                                  # 拜入宗门
sect(action="info", sect_name="天剑宗")                                  # 查看宗门
sect(action="leaderboard")                                               # 宗门战报
leaderboard(type="sect")                                                 # 顶层宗门战榜
```

宗门规则：
- 👤 一人只能属于一个宗门
- ⏳ 退出后 7 天冷却期
- 👑 宗主可任命长老、管理成员
- 🏆 宗门战力 = 宗门灵力 + 成员数 × 50 + 宗门等阶 × 200
- ✅ 开宗立派或拜入宗门成功都会生成可复制分享文案，并直接引导 `sect(action="join")`、`sect(action="leaderboard")`、`leaderboard(type="sect")`、查看 `my_realm`
- ✅ 查看宗门会返回真实宗门快照、公开候选人占位提醒或当前受邀者真实档案快照、入宗试炼命令、拜入命令，并生成社交和 Discussion/PR 可复制招募帖
- ✅ 宗门 action 错误或缺参会披露支持的公开动作，不伪造宗门信息，并返回可复制开宗/入宗/招募命令

宗门等阶：🏕️ 小门派 → 🏯 中等宗门 → 🏔️ 大宗门 → ⛰️ 圣地 → 🌋 超级势力

<br/>

### 📜 第六步：悬赏历练 — 淬炼令

修仙者可以发布悬赏令，请求他人帮忙优化自己的法宝：

```
quest(action="browse")                                                     # 浏览悬赏令
quest(action="post", artifact_name="my-agent", description="Need better error handling")  # 发布悬赏
quest(action="claim", quest_issue_number=42)                               # 认领任务
quest(action="submit", quest_issue_number=42, solution="Added retry with exponential backoff")  # 提交成果
verify_refinement(quest_issue_number=42, refiner="contributor", is_approved=True, feedback="Looks solid")  # 验收成果
```

- ✅ 完成悬赏令 +50 灵力值
- ✅ 悬赏令是突破高阶境界的必经之路
- ✅ 浏览悬赏令会返回 GitHub open Issues 实时悬赏榜，附带直接 `quest(action="claim", quest_issue_number=...)` 认领命令和可复制分享文案
- ✅ 发布悬赏令成功会生成可复制招募文案，并引导道友 `quest(action="claim")`、`quest(action="browse")`、由发布者 `verify_refinement`
- ✅ 悬赏令 Issue 正文与认领/提交/验收评论会包含 `tiangong:refine-*` 标记和已测试解析契约，推广/审核流程可从公开 GitHub 文本恢复法宝、发布者、淬炼者、审核者、结果、下一步命令和来源命令
- ✅ `.github/ISSUE_TEMPLATE` 中的公开 GitHub Issue Forms 暴露 `tiangong:quest`、`tiangong:growth`、`tiangong:season`、`tiangong:tournament`、`tiangong:mentor`、`tiangong:sect` 路由，让外部访客不用预先知道 MCP 命令也能进入修炼循环
- ✅ `.github/workflows/issueops-onboarding.yml` 会用 `issues: write` 给每类 TianGong Issue 路由回帖安全命令卡，不 checkout 代码、不执行仓库脚本、不伪造灵力奖励
- ✅ 认领、提交、验收通过都会生成可复制分享文案，让一张悬赏令完成招募、召回、庆功三段传播
- ✅ 悬赏令 action 错误或缺参会披露支持的公开动作，不伪造成浏览结果，并返回可复制恢复命令
- ✅ 悬赏发布/认领/提交失败会披露真实 GitHub IssueOps 失败快照，不伪造 Issue 或灵力奖励，并返回配置、重试、浏览、搜索、名片、赛季天榜恢复命令
- ✅ 验收失败会披露真实评论/关单/奖励失败快照，不伪造 Issue 关闭或灵力奖励，并返回重试、提交、浏览、名片、赛季天榜恢复命令

## 🔮 法宝品阶系统

<div align="center">

```
⚪ 凡器 → 🟢 灵器 → 🔵 宝器 → 🟣 仙器 → 🟡 神器 → 🔴 太古神器
```

| 品阶 | 符号 | 灵力值门槛 | 附加条件 |
|------|------|-----------|---------| 
| **凡器** | ⚪ | 0 | 刚创建 |
| **灵器** | 🟢 | ≥ 10 | 至少 3 人评价 |
| **宝器** | 🔵 | ≥ 100 | 至少 10 人评价 + README 完善 |
| **仙器** | 🟣 | ≥ 500 | 至少 30 人评价 + 有人贡献改进 |
| **神器** | 🟡 | ≥ 2000 | 至少 100 人评价 + 跨领域影响 |
| **太古神器** | 🔴 | ≥ 10000 | 至少 500 人评价 + 定义新范式 |

### 六维灵根评估

每位评价者从**六个维度**打分（每维 1-10 分）：

| 维度 | 含义 | 对标 |
|------|------|------|
| 📝 铭文 | 描述是否清晰 | README 质量 |
| 🏗️ 阵法 | 架构是否优雅 | 代码架构 |
| ⚙️ 法诀 | 工程是否扎实 | 代码质量 |
| 📖 道统 | 文档是否传承 | 文档完整度 |
| 🛡️ 护体 | 是否稳定可靠 | 鲁棒性 |
| ✨ 悟道 | 是否有创新 | 创新性 |

### 灵力值计算

```
单次评价灵力 = 六维均分 × 评价者境界权重

境界权重：
  炼气期 → 1.0  |  筑基期 → 1.5  |  结丹期 → 2.0
  元婴期 → 3.0  |  化神期 → 5.0  |  婴变期 → 8.0
  问鼎期 → 12.0 |  鲁班 → 80.0   |  天工 → 100.0

示例：
  鲁班打了 5 分 → 5.0 × 80.0 = 400 灵力
  炼气期打了 4 分 → 4.0 × 1.0 = 4 灵力
```

> 一位大师的认可，抵得过五十个新手的评价。**品质，而非数量。**
